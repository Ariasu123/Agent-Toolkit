# Workflows — 三种 AI 开发工作流

AI 编程已经越过"对话框里边聊边写"的阶段，沉淀出几套可复用的工程化工作流。本目录是对三种主流打法的方法论沉淀，来自对它们的实际使用与复盘，不绑定任何具体项目或工具。

| 工作流 | 一句话定位 | 目录 |
|---|---|---|
| **规格驱动** | 规格文档是唯一事实来源；先写规格、人审规格，AI 严格按规格实现 | [spec-driven/](spec-driven/) |
| **自主循环** | 每轮全新 context 反复启动 agent，磁盘文件是唯一记忆，单轮只做一件事 | [ralph-loop/](ralph-loop/) |
| **多 Agent 编排** | 主 agent 只做调度，子代理带干净 context 并行干活，合并集中收口 | [multi-agent/](multi-agent/) |

## 共同地基

三种工作流都站在同两块地基上，缺了哪块都会塌：

1. **上下文工程（AGENTS.md）**：项目的技术约定、硬性要求、反模式写成文件，让每一轮/每一个 agent 都在同一套规则下工作。并行 agent 越多，这份文件越值钱。
2. **可客观验证的验收标准**：测试全绿、构建通过、静态检查干净。"看起来差不多"是所有自主工作流的头号杀手。

## 选型速查

| 任务性质 | 用哪个 |
|---|---|
| 大功能 / 需求复杂 / 要可追溯 | 规格驱动 |
| 批量、可自动验证的机械任务（补测试、清积压 issue） | 自主循环 |
| 大库调研 / 可干净切分的多模块开发 | 多 Agent 编排 |
| 小修小补 | 都不用，直接改 |

三者不互斥，实战中是叠加的：`AGENTS.md` 打地基 → 规格决定做什么 → 独立任务并行加速 → 可验证的部分交给循环跑完 → 人工 review 收口。
