# Ralph Loop — 自主循环

## 核心思想

**每轮以全新 context 启动 agent，磁盘上的文件是唯一记忆。** 一个 `while` 循环反复拉起 agent：读任务清单 → 只做清单上的第一件事 → 验收 → 勾掉清单、提交 → 退出。如此往复，直到清单清空。

Ralph 循环把"长程任务"切成 N 个互不感知彼此的短会话——它不追求一个 agent 一口气做完，而是让一百个"失忆但守规矩"的 agent 接力做完。

## 为什么有效

- **context 不腐烂**：长会话里 LLM 会被自己积累的历史带偏（漂移、遗忘早期约束）。每轮全新 context，漂移在每轮结束时被强制清零。
- **进度可断点续跑**：状态全在磁盘（任务清单 + git 历史），循环崩了、机器重启了，下一轮原地继续。
- **单轮目标极小**："只做一件事"大幅降低了单轮失败的概率；失败也只损失一轮。

## 流程

```bash
cp PROMPT.template.md PROMPT.md   # 替换占位符：验收命令、提交规范
cp plan.template.md plan.md       # 填入任务清单（- [ ] 格式）
AGENT_CMD='kimi -p' ./ralph-loop.sh 8    # 参数：最大轮数
```

[`ralph-loop.sh`](ralph-loop.sh) 不绑定具体 CLI，`AGENT_CMD` 换成 `claude -p`、`codex exec` 等均可。

## 关键设计点

每一条都是用失控换来的：

1. **轮次上限**：永远给循环一个最大轮数。它是所有其他设计失效时的最后兜底。
2. **双重完成判定**：显式信号（agent 输出 `EXIT_SIGNAL: true`）**且**清单中无 `- [ ]` 未完成项，二者同时满足才收敛。只信信号会被幻觉欺骗（agent 声称做完了），只信清单会在 agent 忘记勾选时误判。
3. **死胡同回滚而非死磕**：单轮验收不过且判断思路错误时，`git checkout -- .` 回滚并在清单备注卡点，退出本轮。死磕会把错误层层叠进 context；回滚让下一轮带着干净状态和新视角重来。
4. **可机读的状态块**：每轮强制输出 `RALPH_STATUS`，让驱动脚本和人类都能 grep 出循环的真实进度。

## 失败模式与适用边界

| 失败模式 | 表现 | 对策 |
|---|---|---|
| 任务不可客观验证 | agent 每轮都"觉得完成了"，循环空转 | 验收标准必须是命令（测试/构建），不接受"看起来对" |
| 任务边界不清 | 循环在任务间游荡、反复返工 | 任务拆到"单轮能做完"的粒度再启动 |
| 权限/模式冲突 | 无头模式的 CLI 与提权旗标不兼容，循环每轮秒挂（实战中 `kimi -p` 不能搭配 `--yolo`，8 轮全灭——靠轮次上限兜住） | 启动前先手动空跑一轮验证命令组合 |
| 危险操作无人值守 | 循环里有删库/部署类任务 | 这类任务不进清单；生产环境务必在沙箱中运行整个循环 |

**适合**：批量机械任务、补测试、清积压 issue、"睡前启动早上 review"。
**不适合**：需求模糊的任务、需要人类持续判断的任务、不可回滚的操作。

## 与其他工作流的叠加

- 循环的任务清单可以直接来自[规格驱动](../spec-driven/) tasks 阶段的分解——规格提供了循环必需的"可客观验证"。
- 循环本身只跑单 agent；要并行加速，用[多 Agent 编排](../multi-agent/)在**互不依赖的清单分组**上各起一个循环。
